# SSH 连接弹框

连接过程由一个 `ConnectDialog` 展示建立连接、指纹确认、连接成功三个阶段。沿用 shadcn/ui 组件与主题令牌；已信任主机无需手动确认。成功提示显示 800ms 后自动关闭，也可点击“进入终端”，随后恢复终端输入焦点。

## 状态与边界

- 指纹内容嵌入当前弹框，不再挂载独立的安全弹框。保留拒绝、信任、变更指纹对比和决定失败后的重试；默认焦点为“拒绝”。
- 指纹确认期间，界面展示该请求的真实 endpoint。后台或批量请求仍按队列处理；不根据主机地址猜测它属于哪个前台连接。
- 拒绝指纹只决定对应的 attempt；连接取消仍使用该操作自己的 AbortController。
- 只有终端打开或重连替换成功才展示“连接成功”。完成时释放取消回调，避免关闭成功提示误取消已建立的终端。
- 成功提示被指纹请求遮挡时暂停自动关闭；旧弹框的计时器不能关闭新连接。
- 人工核对指纹时暂停握手网络预算和 SSH 重连的前端兜底计时，确认后恢复剩余预算；显式 context 取消与截止时间仍然生效。
- 后端沿用 `session:attempt` 及现有字段发送 `state: finished`，表示该次 SSH 尝试结束。协调器据此清除对应指纹和排队项，并保留有界的结束 ID 记录以忽略迟到事件。它不代表 PTY 已打开。

## 参考与验证

交互参考 [Netcatty useTerminalEffects](https://github.com/binaricat/Netcatty/blob/main/components/terminal/useTerminalEffects.ts)：连接与指纹交互共用连接表面，异步请求的生命周期应独立处理。

回归覆盖统一弹框、成功停留及焦点、拒绝与重试、并发指纹隔离、取消/失败后的请求清理。交付前运行 `wails3 task ci`，并以浏览器检查深浅主题及窄窗口。
